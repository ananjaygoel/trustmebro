## The Details

Each tier has its own cluster, its own scheduler, and its own glue scripts. NVIDIA OSMO is NVIDIAs answer to that fragmentation: an open-source, Kubernetes-native workflow orchestrator that lets a team describe the whole pipeline in a single YAML file and run it across every tier without touching infrastructure code.

## Why This Matters

Training happens on data-center GPUs. Simulation, physics, and sensor rendering happen on workstation-class RTX hardware. Deployment and hardware-in-the-loop (HIL) testing happen on edge devices such as Jetson AGX Thor, usually on premises.

The AI space continues to evolve at a wild pace, with developments like this becoming more common.

## Key Takeaways

- Each tier usually gets its own tooling, and the handoffs are where custom scripts accumulate.
- OSMO treats all 3 as backends of one control plane.
- Each backend is a Kubernetes cluster registered through the CLI.
- Workflows never name a cluster.

## The Bottom Line

Workflows never name a cluster. They name a platform (for example gb200 , rtx-pro-6000 , or jetson-agx-thor ) and OSMO routes the task to a pool that offers it.
